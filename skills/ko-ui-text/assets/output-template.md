# 출력 형식

audit 모드는 A~D 전부. rewrite 모드는 A 요약 + B + C, 그리고 파일 수정. write 모드는 B(원문 열 없음) + D.

## A. 진단

유형별로. 사례 인용 포함. 개별 문장 나열 금지.

```
### 말투 혼용
"~한다" 선언문과 "~하세요" 지시가 같은 화면에 섞임.
- "카메라를 다른 작업이 잡고 있다" (1b 본문)
- "자세를 잡고 멈추세요" (1f 배너)
- "어두운 칸으로 보드를 옮겨라" (1d 안내)

### 용어 흔들림
| 개념 | 발견된 표기 | 권장 표기 |
|---|---|---|
| ... | ... | ... |
```

## B. 수정 표

| 위치 | 원문 | 수정안 | 역할 | 사유 |
|---|---|---|---|---|

- 위치: id, 컴포넌트명, i18n 키, 화면명+영역 중 식별 가능한 것
- 역할: 화면 제목 / 섹션 헤딩 / 본문 / 버튼 / 라벨 / 상태 배지 / 빈 상태 / 에러 / 잠금 사유 / 툴팁 / 지표 라벨 / 배너 / 토스트 / 다이얼로그
- 사유: 규칙 이름만 짧게. "말투 혼용", "역할 불일치", "중복", "내부 용어", "번역투", "구분 기호"
- 원문 유지가 맞으면 수정안에 "유지"

## D. 결정 필요

맥락 없이 정할 수 없는 항목. 추측해서 고치지 말고 질문으로 남긴다.

- 예: "1e 화면의 독자가 엔지니어라면 fx/fy 지표명을 유지, 운영자라면 '초점 거리'로 풀어쓰기. 어느 쪽인가?"

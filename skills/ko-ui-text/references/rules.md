# 한국어 UI 텍스트 규칙

## 1. 진단 항목

수정 전에 아래 유형으로 반복 패턴을 잡는다. 유형마다 사례 2~3개 인용, 문제인 이유 한 줄.

### 말투 혼용
한 제품 안에서 종결어미가 섞이는가.
- 해요체 지시: "눌러주세요"
- 문어체 선언: "~한다", "~이다", "~라"
- 명령형 해라체: "~하라", "~옮겨라"
- 명사형: "~완료", "~중"
- 합니다체: "~합니다"

문어체 선언이 특히 문제다. 대개 개발자가 설계하면서 쓴 문장이 그대로 화면에 온 것이다.

### 설계 메모 잔존
개발자가 자기한테 쓴 노트가 화면에 남았는가.
"이 화면은 나중에 설계한다", "여기는 자리만 잡아둔다", "TODO", "임시".

### 역할 불일치
- 헤딩에 설명·근거·범위가 들어갔는가
- 버튼이 문장인가
- 라벨에 서술어가 붙었는가
- 빈 상태가 상태만 말하고 다음 행동을 안 알려주는가
- 잠금·비활성 사유가 내부 조건식을 노출하는가

### 중복
헤딩과 바로 아래 본문이 같은 말을 하는가. 배지와 본문이 같은 상태를 두 번 말하는가.

### 용어 흔들림
같은 개념이 화면마다 다른 단어로 불리는가. 반드시 표로 정리한다.

| 개념 | 발견된 표기 | 권장 표기 |
|---|---|---|

### 내부 용어 노출
- 영어 대문자 상태값: READY, ACTIVE, PENDING
- 코드 필드명, 파일명, 변수명
- 영어 음차 전문 용어: 인트린식, 익스트린식, 트랜잭션 (프로젝트가 허용하지 않는 한)
- 수식 기호: |x|, ≥, Σ

### 번역투
- "~를 통해", "~에 대한", "~에 있어서"
- "~을 제공합니다", "~를 지원합니다"의 남발
- 무생물 주어: "이 기능은 ~를 가능하게 합니다"
- "당신", "귀하"
- 영어 어순 그대로 옮긴 긴 수식어
- "~할 수 있습니다"가 문장마다 붙음

### 구분 기호 남용
가운뎃점(·), 하이픈(-), 엠대시(—), 콜론이 문장 속 접속사로 쓰이는가.
모노스페이스 메타데이터 줄에서 항목을 나열하는 가운뎃점은 정상이다. 구분해서 본다.

### 조사·띄어쓰기
- 변수 뒤 고정 조사: `{name}을` (받침 유무로 깨짐)
- 숫자와 단위 띄어쓰기가 화면마다 다름: "3분" vs "3 분"
- 영문과 한글 사이 띄어쓰기 불일치

## 2. 역할별 기준

역할을 벗어난 텍스트가 가장 큰 문제다. 자리에 맞게 다시 쓴다.

| 역할 | 형태 | 길이 | 금지 |
|---|---|---|---|
| 화면 제목 | 명사구 | 10자 내외 | 설명, 부연 |
| 섹션 헤딩 | 명사구 | 15자 이내 | 주장문, 근거, 범위 나열 |
| 본문·설명 | 완결 문장 | 최대 2문장 | 헤딩 반복 |
| 버튼·액션 | 동사 또는 명사 | 2~7자 | 문장, 존댓말 어미 |
| 라벨·필드명 | 명사 | 조사 없이 | 서술어 |
| 플레이스홀더 | 예시 값 또는 짧은 안내 | 1줄 | 라벨 반복 |
| 상태 배지 | 명사 | 5자 이내 | 영어 대문자, 시간 정보 |
| 빈 상태 | 상황 + 다음 행동 | 2문장 | 사과, 감탄사 |
| 에러 | 무엇이 안 됐나 + 뭘 하면 되나 | 2문장 | 원인 코드, 책임 전가 |
| 잠금·비활성 사유 | 사용자가 할 일 한 줄 | 1문장 | 내부 조건식 |
| 툴팁 | 평서문 | 1줄 | 두 문장 이상 |
| 지표 라벨 | 지표 이름만 | 8자 이내 | 기준치 괄호 병기, 수식 기호 |
| 대형 지시 배너 (키오스크) | 해요체 명령 | 12자 이내 | 말끝 흐리기, 두 가지 지시 |
| 토스트 | 결과 한 줄 | 20자 이내 | 설명, 다음 단계 |
| 확인 다이얼로그 | 무엇이 일어나는지 + 되돌릴 수 있는지 | 2문장 | "정말로", "확실히" |

## 3. 말투

- 사용자가 지금 할 동작 → 해요체 명령. "다시 시도해 주세요"
- 시스템 상태 → 명사형으로 끊는다. "동기화 중", "저장 완료"
- 이 둘을 섞지 않는다. 상태 자리에 "저장했습니다"를 쓰면 화면마다 어긋난다
- 문어체 선언("~한다", "~이다")은 UI에 쓰지 않는다
- 사과하지 않는다. "죄송합니다" 대신 무엇을 하면 되는지 쓴다
- 사용자를 탓하지 않는다. "잘못 입력하셨습니다" 대신 "이메일 형식을 확인해 주세요"
- 기본 말투가 합니다체인 프로젝트(금융, 공공, B2B 콘솔)는 지시문도 합니다체로. 프로젝트 설정을 따른다

## 4. 금지

- 하이픈, 엠대시, 콜론, 세미콜론으로 문장 잇기
- 가운뎃점을 문장 속 접속사로 쓰기 (메타데이터 나열은 예외)
- "X가 아니라 Y" 대조 구문
- 괄호로 부연 설명 덧붙이기
- 슬로건 말투: "지금 바로", "더 이상 ~하지 마세요", "새로운 기준", "~의 시작"
- 느낌표 (축하·완료 외)
- 이모지 (명시적 요청 외)
- "~해 보세요"의 남발. 권유가 아니라 지시면 "~하세요"

## 5. 판단이 애매하면

- 소리 내어 읽어서 어색하면 다시 쓴다
- 이 문장이 없어도 사용자가 다음 행동을 아는가. 안다면 지운다
- 좁은 화면(모바일, 키오스크)에서 두 줄 넘어가면 줄인다
- 원문이 이미 자연스러우면 손대지 않는다. "유지"로 표기한다
- 프로젝트 용어집과 "더 자연스러운 표기"가 충돌하면 용어집이 이긴다. 통일이 우선이다
- 독자가 개발자·엔지니어인 화면은 지표명과 영어 약어 허용 범위를 넓힌다. 단 말투와 역할 규칙은 그대로다

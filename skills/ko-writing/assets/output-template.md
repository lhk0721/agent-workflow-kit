# 출력 형식

audit 모드는 A~D 전부. rewrite 모드는 A 요약 + B + C, 그리고 파일 수정.
write 모드는 결과물 + D만.

## A. 진단

유형별로. 사례 인용 포함. 개별 문장 나열 금지.

```
### 번역투
영어 어순과 "~를 통해" 구문이 문서 전반에 깔림.
- "설정을 통해 동작을 제어할 수 있습니다" (README 12줄)
- "해당 이슈에 대한 대응이 필요합니다" (설계 문서 3절)

### 근거와 추정 뒤섞임
실측값과 짐작이 같은 말투로 쓰임.
- "카메라가 프레임을 빠뜨려서 깨집니다" (원인 미확인)
```

## B. 수정 표

| 위치 | 원문 | 수정안 | 사유 |
|---|---|---|---|

- 위치: 파일명 + 줄번호, 또는 문서명 + 헤딩
- 사유: 규칙 이름만 짧게. "번역투", "AI 말투", "결론 실종", "근거·추정", "벽글",
  "용어 흔들림", "구분 기호", "표기"
- 원문 유지가 맞으면 수정안에 "유지"

## D. 결정 필요

맥락 없이 정할 수 없는 항목. 추측해서 고치지 말고 질문으로 남긴다.

- 예: "이 문서의 독자가 팀 동료라면 배경 절을 지우고, 외부 사용자라면 남긴다. 어느 쪽인가?"
